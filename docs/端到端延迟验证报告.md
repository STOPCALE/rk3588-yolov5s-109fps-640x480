# 端到端延迟验证报告（LED 光参照法）

> **定位**：回答一个一直挂着的问题——**"现实世界正在发生的事，板子上的结果要滞后多久？"**
> 2026-10-01 完成验证（含方法迭代：V4L2 内核戳 → 屏幕毫秒时钟 → **LED 光参照**）。
> **一句话结论**：**球类连续目标 ≈ 34ms；突发光事件 ≈ 38ms（33~44ms）**。
> 拆解：相机拾取段 **8.8ms** + 软件段 **24.3ms**；关键常数由两条独立证据链交叉验证。

## 1. 问题的准确表述与三条测量路径

**问题**："现实（光子）→ 板子结果可用"的绝对延迟是多少？——原需求见 `00` §4
（"实时推理得到的结果，要和显示的行动相差不大"；**要的是端到端延迟小，不是帧率高**）。

三条路径（全部在一晚内完成，前两条弃用、第三条成立）：

1. **V4L2 内核时间戳**（`v4l2_time_probe`，成立，作为佐证）
   - 测"帧内核完成 → 用户态可见"：buf=2 时 **8.08ms 中位**（8.64 均值）；buf=1 反而丢半帧无延迟收益。
   - 局限：不含曝光/读出（ts 语义未定），不能单独给"绝对延迟"。
2. **屏幕毫秒时钟法**（`screen_clock`，**弃用**）
   - 屏幕显示板子墙钟 → 相机拍屏 → 读帧图时钟对账。
   - 实测"屏幕数字 → 结果" ≈ 90ms；反推**屏幕显示链自身 ≈ 50ms**（X 渲染/合成/面板/刷新等待），
     是"参照物自带延迟"，不适合精密测量（但作为"投屏代价"的真实数据保留）。
3. **LED 光参照法**（`led_seq_probe` + `led_flash.sh`，**成立，主方法**）
   - 板载 `status_led` 由板子直接开关，**发光时刻由板子 µs 级记录**（与日志同一时间轴）；
   - 相机逐帧记录"ROI 绿点亮度 + 帧时间戳"；
   - **关键技巧**：曝光只 2.5ms，跳变恰被"切开"的帧亮度是中间值，**可从亮度分数反解跳变在曝光窗内的位置** → 单样本精度 ≤ 曝光时长。

## 3. 数据与推导

### 3.1 两个"高精度样本"（核心证据）

| 样本 | 方向 | 亮度分数 r | 跳变在窗内位置 | 推算 C = 曝光结束→拿到帧 |
|---|---|---|---|---|
| #1 | 灭→亮 | 0.588 | t_led = E_end − 0.588×2.5ms | **8.80 ms** |
| #2 | 灭→亮 | 0.878 | t_led = E_end − 0.878×2.5ms | **8.85 ms** |

两个独立样本一致到 **0.05ms**。

### 3.2 全体跳变的一致性（23 个区间样本）

- 帧侧共 25 个新态首帧（窗口内全捕获）；`Δ_ub = wall(首帧) − t_led` 分布 **10.3 ~ 22.6ms**；
- 理论范围 = C + P（P = 0~gap+2.5ms，相位项）→ 10.3~22.6 完全落入模型，无异常；
- 下确界 10.27ms ≥ C 与 8.8 自洽（P≥0）。

### 3.3 交叉验证

- **内核戳**（独立工具）：帧完成→可见 8.08~8.64ms ≈ C + ε ✔；
- **屏幕法**（独立方法）：90ms = 屏幕链(~50) + C+E[P](~13.4) + 软件段(26.7) ✔；
- **预算对照**：旧文档预算 L_min ≈ 37ms（1/fps + 24.9 + 后处理）——实测 34~38ms，预算被证实。

## 4. 口径说明（引用的前提）

1. **"球"与"事件"是两种口径**：球是连续目标（不存在"等采样"项），取曝光中点；
   突发事件要加 0~9.1ms 随机相位（均值 4.6ms）。
2. **平均延迟可补偿，抖动才致命**（`00` §4 原则）：本链路已经"小 + 稳定 + 可测"——
   37 秒零漂移、软件段 ±1ms；对球跟踪场景，恒定延迟可被弹道模型完全外推补偿。
3. **预测器线索**：`trajectory_predictor.hpp` 的 `lead_ms=25` 对应"软件段（B8-3 实测）"，
   但球的历史点对应**曝光中点**（比采集戳早 ~10ms）→ 若目标是"包送达时刻的球位置"，
   **lead 可能欠补 ~10ms（25 → ~34~35）**，建议用 `predictor_eval` 在真实球场景核对。

## 5. 工程含义（简）

| 场景 | 影响 |
|---|---|
| 球轨迹跟踪 / 落点预测 | ≈ 无影响（恒定延迟可外推补偿；补偿设在 lead_ms 上） |
| 突发/不可预测事件（碰撞变向） | 认知滞后 ~38ms（球在此间走 0.3~0.9m） |
| 闭环控制（未来机器接球） | 回路相位滞后项；机械响应才是大头；已接近物理下限 ~32ms |
| 投屏展示 | 叠加屏幕链 ~50ms → 总计 ~84ms（低延迟显示器可减） |
| 测量/记录/判断 | 无关（时间戳准确即可） |

## 7. 教训（本次新增，已同步至手册）

1. **参照物先标定自身延迟**：屏幕显示链 ~50ms → 测量"瞬间事件"首选 µs 级光源（LED）。
2. **`auto_*` 是稳定的敌人**：连续自动对焦每次开流重新收敛（取景漂移 100+ px）；
   自动曝光毁掉亮灭差分。测量前锁死 focus/exposure/WB，且**布置冻结**（手持=废数据）。
3. **口径先定义再测**："平均延迟"必须说清含不含采样相位、对球还是对事件。
4. **先锁频再测**（例行公事，本次再次验证：未锁频时 76.6fps/波动巨大）。
