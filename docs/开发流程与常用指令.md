## 1. 一次性配置（每台新电脑只做一次）

### 1.1 SSH 免密登录

**① PC 上生成密钥（已有则跳过）**

```cmd
ssh-keygen -t ed25519 -C "windows-pc"
```

一路回车，密码留空。

**② 把公钥装到板子**

cmd：
```cmd
type %USERPROFILE%\.ssh\id_ed25519.pub | ssh orangepi@192.168.3.226 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

PowerShell：
```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh orangepi@192.168.3.226 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

**③ 验证（不输密码直接输出 OK 即成功）**

```cmd
ssh orangepi@192.168.3.226 "echo OK"
```

### 1.2 配置 SSH 别名（强烈推荐，命令能短一半）

新建/编辑 `C:\Users\<你的用户名>\.ssh\config`（**文件名必须是 `config`，没有扩展名**）：

```ssh-config
Host board                  # ← 这里写的是"别名"，名字随便起
    HostName 192.168.3.226  # ← 这里才是真正的 IP / 域名
    User orangepi
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 6
```

> 🔴 **最容易搞错的点：`Host` 后面跟的是「别名」，不是 IP。**
>
> - 写成 `Host 192.168.3.226` → 你只能用 `ssh 192.168.3.226`，
>   而 `ssh board` 会报 `Could not resolve hostname board`
> - 别名想叫什么就叫什么（`board` / `rk3588` / `orangepi` 都行），关键是 `HostName` 里填对 IP
> - 编辑器把它存成 `config.txt` **也不行**，SSH 只读 `config`
> - 改完 config 后，**已经开着的终端不会重新读取**，需要重开一个 PowerShell

完整的样子（可以写多段，SSH 按顺序匹配）：

```ssh-config
Host board
    HostName 192.168.3.226
    User orangepi
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 6

Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/id_ed25519
```

配好后：

| 原命令 | 简写 |
|---|---|
| `ssh orangepi@<板子IP>` | `ssh board` |
| `scp f.txt orangepi@<板子IP>:~/` | `scp f.txt board:~/` |
| `git clone orangepi@<板子IP>:~/myproj.git` | `git clone board:~/myproj.git` |
| VS Code Remote-SSH 主机 | `board` |

### 1.3 板上的 Git 身份（每个新仓库一次）

```bash
cd ~/myproj
git config user.name  "orangepi"
git config user.email "orangepi@orangepi5"
```

### 1.4 ⭐ 开发板 IP 变了怎么办

板子用 **DHCP 动态获取**地址，所以**路由器重启、租约到期、换了网络**都会导致 IP 变化。表现是：

```
ssh: Could not resolve hostname board: Name or service not known
ssh: connect to host 192.168.x.x port 22: Connection timed out
```

#### 第 1 步：找出新 IP

| 方法 | 操作 | 备注 |
|---|---|---|
| **路由器后台** | 登录路由器 → DHCP 客户端列表 → 找主机名 `orangepi5` | 最可靠 |
| **板子接显示器** | 登录后执行 `hostname -I` | 需要键鼠显示器 |
| **PC 扫 ARP 表** | `arp -a \| findstr 192.168` | 板子近期通信过才有记录 |
| **网段扫描** | `1..254 \| % { ping -n 1 -w 50 192.168.3.$_ > $null }; arp -a` | 兜底手段 |

#### 第 2 步：改配置（一条命令）

```powershell
cd "E:\desk\学习\C++\mytest\new"

.\tools\set-board-ip.ps1                  # 不带参数 = 只查看当前地址
.\tools\set-board-ip.ps1 192.168.3.231    # 换成新 IP
.\tools\set-board-ip.ps1 orangepi5.local  # 或换成 mDNS 主机名
```

脚本会自动：

- 只改 `.ssh/config` 里 **`Host board` 段的 `HostName`**（不会误伤 github 那段）
- 先备份到 `config.bak`
- 校验参数格式（IPv4 或主机名）
- 以 **UTF-8 无 BOM** 写回（保留中文注释，且不会让 OpenSSH 报 `Bad configuration option`）

> ✅ **`tools\sync.ps1` 不需要改** —— 它引用的是别名 `board`，别名指向哪它就跟着去哪。
> 整个工程里写死 IP 的地方**只有 `.ssh/config` 一处**。

#### 第 3 步：验证

```powershell
ssh board "echo OK"        # 输出 OK 即恢复
```

#### ⭐ 根治：让 IP 变化彻底不再影响你（三选一）

| 方案 | 做法 | 评价 |
|---|---|---|
| **mDNS 主机名**（先试这个） | PC 上 `ping orangepi5.local`；通了就执行 `.\tools\set-board-ip.ps1 orangepi5.local` | 最省事，一劳永逸 |
| **路由器 DHCP 保留** | 路由器后台把板子的 MAC 绑定到固定 IP | 最稳，不用动板子 |
| **板子静态 IP** | 板子上用 `nmcli` 配置 | 彻底，但配错会断网 |

**关于 mDNS**：Windows 10 1803+ **原生支持**，不需要装 Bonjour。不通的话在板子上检查服务：

```bash
systemctl status avahi-daemon          # 没装就: sudo apt install avahi-daemon
```

**关于静态 IP**：

```bash
nmcli connection show                                     # 先查连接名
sudo nmcli connection modify "<连接名>" ipv4.method manual \
     ipv4.addresses 192.168.3.231/24 ipv4.gateway 192.168.3.1 \
     ipv4.dns "192.168.3.1 8.8.8.8"
sudo nmcli connection up "<连接名>"
```

> ⚠️ **网关和 DNS 必须换成你自己网络的**，写错会直接断网 —— 那时只能接显示器去救。
> 另外：用**网线**比 WiFi 稳定得多（路由器重启后 WiFi 经常重新分配 IP）。

## 2. 工作模式：**PC 是唯一真源，板子只做编译/验证**

```
┌─────────────────────────────────┐         ┌────────────────────────────────┐
│  Windows PC  ← 唯一真源           │         │  RK3588 开发板 (只读部署目标)     │
│                                 │         │                                │
│  VS Code (本地模式, 全速编辑)      │         │  /home/orangepi/myproj         │
│    ↓ 编辑                        │         │    ├── CMakeLists.txt          │
│  E:\desk\学习\C++\mytest\new      │         │    ├── src/ include/ model/    │
│                                 │         │    └── build/  install/        │
│  git commit → git push ─────────┼──SSH───►│  /home/orangepi/myproj.git     │ ← 裸仓库
│                                 │         │           ↑                    │
│                                 │         │    git pull --ff-only          │
│                                 │         │           ↓                    │
│                                 │         │  cmake --build → 运行验证        │
└─────────────────────────────────┘         └────────────────────────────────┘
```

**核心规则（务必遵守）：**

| 规则 | 原因 |
|---|---|
| **只在 PC 上编辑代码** | 本地编辑全速响应，体验最好 |
| **板子上永远不编辑、不 commit** | 板子只 `git pull --ff-only`，保证永远不会分叉 |
| **同步只用 Git，不再用 scp 传代码** | scp 传单文件容易漏、容易覆盖，是之前"改了不生效"的根因 |
| **`build/`、`install/` 不进 Git** | 已在 `.gitignore` 中 |
| **板子只负责"编译→运行→把报错贴回来"** | 定位清晰，不产生第二份需要维护的源码 |

## 3. 日常开发流程

1. VS Code 打开本地目录 **`E:\desk\学习\C++\mytest\new`**（注意是**本地模式**，左下角不显示 `SSH:`）
2. 打开一个 PowerShell 终端备用（用来同步到板子）

两种方式，任选。

**方式 A：一条命令搞定（推荐，见 `tools\sync.ps1`）**

```powershell
cd "E:\desk\学习\C++\mytest\new"

```

脚本会依次完成：`git commit` → `git push` → 板子 `git pull` → 板子 `cmake --build`。

**方式 B：手动分两步**

```powershell
# ① PC 上：提交并推送
cd "E:\desk\学习\C++\mytest\new"
git add -A
git commit -m "描述这次改了什么"
git push board master
```

```bash
# ② 板子上：拉取 + 编译
ssh board
cd ~/myproj
git pull --ff-only

# 只在 CMakeLists.txt 改动后或新增/删除源文件后才需要重新配置
cmake -B build -S .
cmake --build build -j8
cmake --install build
```

**直接一条 SSH 命令完成（不开交互终端）：**

```powershell
ssh board "cd ~/myproj && git pull --ff-only && cmake -B build -S . && cmake --build build -j8"
```

### 3.2.1 运行验证

```bash
# 板子上
cd ~/myproj/install/my_rknn_yolov5_demo_aarch64
./my_rknn_yolov5_demo ./model/RK3588/best.rknn <视频路径>
```

> ⚠️ 板子目前**没有摄像头**，`<视频路径>` 请传视频文件，不要传 `0`。

> 增量编译时 `cmake -B build -S .` 可以省略，直接 `cmake --build build -j8`。
> 但**新增/删除源文件后必须重新配置**。

### 3.3 新增源文件时的固定动作

1. 创建 `src/xxx.cc`
2. 在 `CMakeLists.txt` 的 `add_executable` 里**加一行** `src/xxx.cc`
3. `cmake -B build -S .` 重新配置
4. `cmake --build build -j8`

**CMake 规定：`add_executable` 里列出的每个文件都必须真实存在**，否则报
`Cannot find source file: ...`。还没写的文件可以先注释掉：

```cmake
add_executable(my_rknn_yolov5_demo
        src/main.cc
#        src/postprocess.cc
#        src/preprocess.cc
)
```

### 3.4 把板子上的报错日志取回本地

编译失败时，拉回本地慢慢看比在 SSH 里滚屏舒服：

```powershell
# 编译并把完整输出存到板子的 /tmp/build.log
ssh board "cd ~/myproj && cmake --build build -j8 2>&1 | tee /tmp/build.log"

# 拉回本地
New-Item -ItemType Directory -Force -Path "E:\desk\logs" | Out-Null
scp board:/tmp/build.log "E:\desk\logs\build.log"
```

只想看最后的错误：

```powershell
ssh board "cd ~/myproj && cmake --build build -j8 2>&1 | tail -40"
```

**PC 就是真源，所以"从板子备份"这一步不再需要了。** 要做的是把 PC 的仓库推到远端：


### 3.6 ⭐ 收工流程与安全关机（重要！避免仓库损坏）

#### 背景：为什么要专门讲这个

板子的根文件系统是 ext4，启动日志里明确写着 **writeback 数据模式**：

```
EXT4-fs (mmcblk1p1): mounted filesystem with writeback data mode
```

这意味着**写操作会先在内存（page cache）里停留，过一会儿才真正落盘**。如果此时直接断电，那些"还没落盘"的文件就会变成**全零**。

> 🔴 **本工程已经因此出过一次事故**：`.git/index` 和 `refs/heads/master` 同时被零填充，
> 板子上的 Git 仓库整体报废，只能推倒重建。

#### 正确关机（在板子上）

```bash
sync                  # ① 可选但推荐：手动刷盘，确认没有报错
sudo poweroff         # ② 用命令关机（⚠️ 不要直接拔电、也不要长按电源键）
```

**然后等下面任一现象出现，才算关机完成：**

- 电源指示灯熄灭（或转为待机色）
- HDMI 显示器黑屏、不再有输出
- 板子上的风扇 / 网口灯停止活动

**最后才断电 / 拔电源。**

#### ❌ 这些做法会导致数据损坏

| 做法 | 后果 | 严重度 |
|---|---|---|
| 直接拔电源 / 长按电源键强关 | 正在写的文件变全零 | 🔴 Git 仓库、配置都可能报废 |
| 不关机就拔 SD 卡 | 同上，且更严重 | 🔴 |
| `git push` / `git pull` 进行中关终端或断 SSH | 可能中断引用更新，留下损坏的 ref | 🟠 |
| `cmake --build` 进行中强行断电 | 编译产物损坏 | 🟡 重新编译即可 |

#### 正确"退出"（分情况，别混）

| 操作 | 正确做法 | 说明 |
|---|---|---|
| **退出 SSH 会话** | `exit` 或 `Ctrl+D` | ✅ 安全。**只是断开你和板子的连接，板子继续运行** |
| 关掉 PC 上的终端窗口 | 直接关 | ✅ 安全，板子不受影响 |
| 中断正在运行的命令 | `Ctrl+C` | ✅ 一般安全，但**别在 `git push/pull` 中途按** |
| 中断编译 | `Ctrl+C` | ✅ 安全，重新 `cmake --build build -j8` 即可 |
| 挂起一个卡住的进程 | `Ctrl+Z` 然后 `kill %1` | ⚠️ 别用 `kill -9` 杀正在写文件的进程 |
| **关闭板子** | `sudo poweroff` + 等指示灯灭 | ⭐ 见上 |

> ⭐ **关键区别**：
> `exit` = 断开连接，板子照常运行；
> `poweroff` = 关掉板子。
>
> **日常收工只需要 `exit`，不需要关板子。** 只有要断电、拔卡、搬动板子时才 `poweroff`。

#### 日常收工清单

```
① 【PC】确认代码已提交推送： .\tools\sync.ps1 -Message "收工"
② 【PC】关掉 VS Code / 终端窗口          （安全，不影响板子）
③ 【板子】要拔电才需要： sync → sudo poweroff → 等指示灯灭 → 断电
```

#### 如果真的遇到损坏

**典型症状：**

```
error: 坏的签名 0x00000000
fatal: 索引文件损坏

warning: 忽略损坏的引用 refs/heads/master
error: cannot lock ref 'refs/heads/master': unable to resolve reference ... reference broken
```

**处理方式：不要试图修复，直接推倒重建。**（因为 PC 上有完整的权威副本）

```bash
# 第 1 步【板子】
cd ~
mv myproj myproj.old              # 改名保留，不直接删
rm -rf myproj.git
git init --bare myproj.git

# 第 2 步【PC】
cd "E:\desk\学习\C++\mytest\new"
git push -u board master

# 第 3 步【板子】
cd ~
git clone myproj.git myproj
cd ~/myproj
cmake -B build -S . && cmake --build build -j8 && cmake --install build

# 第 4 步【板子】确认一切正常后
rm -rf ~/myproj.old
```

> ✅ **为什么不用慌**：**PC 是唯一真源**，板子上的仓库只是"运行副本"。
> 板子坏了、仓库毁了，**代码一行都不会丢** —— 这正是我们坚持"板子只读"原则的价值。

#### 额外保险

| 措施 | 说明 |
|---|---|
| **定期推到 GitHub / Gitea** | 见 §3.5。PC 硬盘也会坏，异地备份才是最后一道防线 |
| **用带开关的插座** | 减少"拔线"这种粗暴断电 |
| **怀疑存储有问题时** | 板子上跑 `dmesg \| grep -iE "I/O error\|mmc\|ext4"`，看有没有报错 |
| **启动时自动 fsck** | 板子上 `sudo touch /forcefsck && sudo reboot`，下次启动会检查文件系统 |

### 5.5 常见 Git 故障恢复

| 现象 | 原因 | 解决 |
|---|---|---|
| `not in a git directory` | `git config` 跑在 `git init` 之前 | 先 `git init` |
| `src refspec master does not match any` | 本地分支名不是 `master`（可能是 `main`） | `git branch -M master` |
| `Could not resolve hostname board` | SSH 别名没配或没生效 | 检查 `~/.ssh/config` 的 `Host board` 段；重开终端 |
| `destination path 'xxx' already exists` | 目录已存在 | `rmdir /s /q xxx`（cmd）或 `Remove-Item -Recurse -Force xxx` |
| `You appear to have cloned an empty repository` | 源仓库没有任何 commit | 先在源仓库 `git add -A && git commit` |
| `refusing to merge unrelated histories` | 两边历史无关（各自 `git init` 过） | `git push -f`（PC）或板子 `git reset --hard origin/master` |
| `! [rejected] ... non-fast-forward` | 板子上有本地提交，和 PC 分叉了 | 板子执行 `git reset --hard origin/master`（板子本就该只读） |
| `Your local changes would be overwritten` | 板子工作区有未提交改动 | 板子执行 `git reset --hard`（会丢弃改动） |
| 提交时提示 `请告诉我您是谁` | 没配 Git 身份 | `git config user.name/user.email` |
| 想撤销最近一次提交但保留改动 | — | `git reset --soft HEAD~1` |
| 想丢弃所有未提交改动 | — | `git reset --hard HEAD` |
| 想丢弃未跟踪的新文件 | — | `git clean -fd`（⚠️ **不加 `-x`**，否则会删掉 `build/`、`install/`） |

### 5.6 板子"只读"原则

| 板子上允许 | 板子上禁止 |
|---|---|
| `git pull --ff-only` | `git commit` |
| `git log` / `git status` / `git diff` | `git add` |
| `git reset --hard`（用于对齐，会丢弃改动） | 直接编辑源码文件 |

> **一旦板子上产生了提交，PC 的 `git push` 就会变成 non-fast-forward 而被拒绝。**
> 记住了：板子只负责"拉下来、编出来、跑起来"。

## 6. 排错手册

| 报错 | 原因 | 解决 |
|---|---|---|
| `Could not resolve hostname board` | ① SSH 别名没配 ② **板子 IP 变了**（DHCP 重新分配） | 检查 `~/.ssh/config` 的 `Host board` 段；IP 变了执行 `.\tools\set-board-ip.ps1 <新IP>`（**详见 §1.4**） |
| `Connection timed out` / `No route to host` | 板子没开机、**IP 变了**、或不在同一网段 | 先 `ping <板子IP>` 确认能通；变了见 §1.4 |
| `Host key verification failed` | 换了板子 / 重装了系统，指纹变了 | `ssh-keygen -R <板子IP>` 清掉旧指纹再连 |
| `Permission denied (publickey)` | 公钥没装到板子上 | 重跑 §1.1 的"把公钥装到板子" |
| `does not appear to contain CMakeLists.txt` | 文件名大小写错了（如 `CmakeLists.txt`） | Linux 区分大小写，改名 |
| `cmake: 未找到命令` | 板子没装 cmake | `sudo apt install -y cmake build-essential libopencv-dev pkg-config` |
| `Cannot find source file: src/xxx.cc` | `add_executable` 里列了不存在的文件 | 注释掉或创建该文件 |
| `No SOURCES given to target` | 上一条的连带（目标没有任何有效源文件） | 同上 |
| `Generate step failed` | 上一条的连带 | 同上 |
| `没有指明目标并且找不到 makefile` | 上一步 generate 失败，`build/` 里没有 Makefile | 修好 CMake 错误后 `rm -rf build` 重来 |
| `flags.make: 没有那个文件或目录` | 还没成功编译过（该文件是编译时生成的） | 先让 `cmake --build` 成功 |
| `OpenCV_FOUND to FALSE ... components were not found` | 组件名写错或该模块没编进 OpenCV | 检查 `COMPONENTS` 拼写；按"符号所在的库"选组件 |
| `undefined reference to cv::VideoCapture::...` | 用了 `VideoCapture` 但没链 `videoio` | `COMPONENTS` 里加 `videoio` |
| `undefined reference to TrajectoryPredictor::...` | 只写了头文件，没加对应的 `.cc` | 把 `.cc` 加进 `add_executable` |
| `error while loading shared libraries: xxx.so` | RPATH 不对 / 库不在搜索路径 | 确认 `CMAKE_INSTALL_RPATH` 是 `$ORIGIN/lib`；或临时 `export LD_LIBRARY_PATH=$PWD/lib` |
| `symbol lookup error: xxx: undefined symbol` | 链接期放宽了符号检查，运行期真缺符号 | 检查 `.so` 版本是否匹配 |
| `/bin/bash^M: bad interpreter` | 脚本是 CRLF 行尾 | 板子上 `sed -i 's/\r$//' *.sh`；或 VS Code 设 `"files.eol": "\n"` |
| `git commit` 提示"请告诉我您是谁" | 没配 Git 身份 | `git config user.name/user.email` |
| `You appear to have cloned an empty repository` | 源仓库没有任何 commit | 先在源仓库 `git add -A && git commit` |
| `destination path 'xxx' already exists` | 上次 clone 留下的目录 | 删掉该目录再 clone |
| **`error: 坏的签名 0x00000000`** + **`fatal: 索引文件损坏`** | 🔴 **存储层损坏**（多半是直接断电），`.git/index` 被零填充 | **别修，直接重建** → 见 **§3.6**「如果真的遇到损坏」 |
| **`cannot lock ref ... reference broken`** / **`忽略损坏的引用`** | 同上，`refs/heads/master` 被零填充 | 同上 → **§3.6** |
| `'origin' does not appear to be a git repository` | 板子上的 `~/myproj` 是 `git init` 出来的，**没有 origin remote** | 板子 `git remote add origin ~/myproj.git`；或直接重新 clone（§3.6） |
| `! [rejected] master -> master (fetch first)` | 两边的 Git 历史**无关**（不是同一条线） | 让 PC 重新推送：板子重建空裸仓库 → PC `git push -u board master` |
| `build/`、`install/` 被误提交进 Git | 🔴 `.gitignore` **是空文件**（建了文件但内容没写） | 填好 `.gitignore` 并 `git rm -r --cached build install`；注意**不要用带 BOM 的 UTF-8** 写，否则第一条规则失效 |
| 注释/中文乱码 | 文件用 GBK 存、按 UTF-8 读 | VS Code 右下角编码 → `Save with Encoding → UTF-8` |
| 改了代码但结果没变 | 编辑与 scp 混用，文件被覆盖 | 用 `md5sum` 对比两边；统一只在一处编辑 |

## 7. 注意事项（踩过的坑，别再踩）

1. **`cmake_minimum_required(VERSION 3.16)`** —— 板子上是 3.16.3，**不要再提高这个版本号**。
2. **`CMAKE_BUILD_TYPE` 必须有默认值**，否则 `CMAKE_<LANG>_FLAGS_<CONFIG>` 全部失效，
   编译出来是 `-O0`（性能腰斩）。
3. **`CMAKE_INSTALL_RPATH` 用 `$ORIGIN/lib`**，不要用绝对路径或相对 CWD 的 `lib`
   （前者换目录失效，后者必须 `cd` 到安装目录才能跑）。
4. **`install(DIRECTORY model ...)` 不要加结尾斜杠** —— 加了会丢掉 `model/` 这一层，
   而代码里硬编码了 `./model/coco_80_labels_list.txt`。
5. **一个 `-I` 路径要精确到"装着 `.h` 的那个目录"**，不是它的祖先目录。
6. **OpenCV 组件按"符号所在的库"选**，不是按头文件
   （`highgui.hpp` 会间接 include `videoio.hpp`，容易造成"编译过、链接炸"）。
7. **串口 `/dev/ttyS4` 需要权限**，当前用户若不在 `dialout` 组，需
   `sudo usermod -aG dialout $USER` 后重新登录。
8. **`/dev/rga` 与视频设备需要 `video` 组权限。**
9. **板子 IP 是 DHCP 动态分配的**，重启/租约到期可能变化 → 连不上时先看 **§1.4**。
   建议在路由器上做 **DHCP 保留**，或改用 mDNS 名 `orangepi5.local`，一劳永逸。
   工程里**只有 `.ssh/config` 一处**写死了 IP，用 `.\tools\set-board-ip.ps1` 改即可。
10. 🔴 **关机必须用 `sudo poweroff`，等指示灯灭再断电** —— 直接拔电会让"正在写的文件"变成全零。
    本工程已因此报废过一次 Git 仓库（`.git/index` 和 `refs/heads/master` 被零填充）。
    **日常收工只需要 `exit` 断开 SSH，不需要关板子。** 详见 **§3.6**。
11. **`.gitignore` 写好后要用 `Get-Content` 看一眼内容非空** ——
    本工程出过一次"文件建了但内容没写"，导致 `build/`、`install/` 被误提交。
    另外**别用带 BOM 的 UTF-8 写 `.gitignore`**（PowerShell 5.1 的 `-Encoding UTF8` 会加 BOM），
    BOM 会让第一条规则失效。
