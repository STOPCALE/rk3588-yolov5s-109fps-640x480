## 一、三层结构

```
应用层  main.cc：--serial <dev>，结果循环直发 + 统计（151/151，失败0）
   │
协议层  serial_proto.hpp：15B 组包 + CRC-8（双实现对照自测）
   │
驱动层  uart.c：termios 裸模式 + write 循环 + tcflush（回环 LOOPBACK PASS）
```

## 二、termios 裸模式（7 处改进，核心 6 条）

| # | 改进 | 为什么 |
|---|---|---|
| 1 | 检查 `tcgetattr/tcsetattr` 返回值 | 静默失败 = 配置没生效 |
| 2 | 清 **INLCR/IGNCR/ICRNL** | **0x0D↔0x0A 翻译会破坏二进制字节流**（CRC 直接崩） |
| 3 | 清 **CRTSCTS** | 硬件流控不是我们要的（对端未必支持） |
| 4 | 弃 `O_NDELAY`，改 **VMIN=0/VTIME=0** | 没数据就返回 0，不忙等、不阻塞 |
| 5 | `write` **循环**处理部分写 + **EINTR** 重试 | 内核缓冲不保证一次写完；信号会打断 |
| 6 | `tcflush` 清残留 | 上一次连接/噪声留下的半包会污染解析 |

> ⭐ 冷知识：termios 配置**粘在设备上**——程序退出后设置仍生效
> （跑前 `stty` 显示 9600/min=1，跑后 115200/min=0）。所以每次打开都要**重新配置**（uart_open 的做法）。

## 三、15 字节协议（帧结构）

| 字节 | 内容 | 编码 | 实抓包例子（`A5 00 20 FF ED 00 00 00 00 00 30 01 00 A9 5A`） |
|---|---|---|---|
| [0] | 帧头 | 固定 **0xA5** | A5 |
| [1..2] | dx（相对图像中心） | int16 **大端**（含符号） | `00 20` = **+32**（=352.3−320） |
| [3..4] | dy | int16 大端 | `FF ED` = **−19**（=221−240） |
| [5..6] | vx | int16 大端 | `00 00` = 0（首帧无速度） |
| [7..8] | vy | int16 大端 | `00 00` = 0 |
| [9..10] | r（半径） | int16 大端 | `00 30` = **48**（=round(48.2)） |
| [11] | det（本帧是否有检测） | u8 | 01 |
| [12] | pred（是否为预测值） | u8 | 00（首帧 pred=0） |
| [13] | CRC-8（前 13 字节） | u8 | **A9**（已独立验算） |
| [14] | 帧尾 | 固定 **0x5A** | 5A |

**CRC-8**：逐位实现（非反射变体，与原工程一致；注意资料里的 `A1` 是反射变体，
标准检验串 "123456789" → **0xF7**）。双实现对 200 组随机数据全部一致。

**发送开销**：`uart_write` 平均 **6~7 µs**（只是写进内核发送缓冲）；
"上线"由 UART 硬件后台完成（1.3 ms，见手算）→ **加串口后 101.2 fps 零变化**。

## 四、轨迹预测器（真实时间戳 + 门限选择）

**三状态机（v2）**：

| 状态 | 策略 |
|---|---|
| 正常跟踪 | 门限 `gate_px=100`：按上次速度外推的"预期位置±100px"内**选最近**（不选最高分） |
| 丢失 ≤5 帧 | 用缓存速度**外推**（predict 继续输出，detect=0） |
| 丢失 >5 帧 | 清轨道、保留**锚点**；只在锚点 ±`relock_px=250` 内重锁；锚点 5s 超时才全局重锁 |

**两个必修的坑**：① 每帧选最高分 → 目标跳变 33 次、预测被污染（B8-4 v0 的教训）；
② v1 的"全局重锁"会被**静止误检**抢占（r≈16px 的桌面杂物）——所以要有锚点半径。
③ 启动连发帧（Δt≈3ms）把速度估计带飞（76.99px）→ `min_dt_ms=5` 保护（→6.86px）。

## 七、硬约定

1. 二进制协议：**三个翻译位必须为零**（ICRNL/INLCR/IGNCR）；
2. 每次打开串口都要**重新配置**（配置是"粘"的）；
3. 发送=**6µs 级**（写缓冲），别把 1.3ms 算进主循环；
4. 预测必须用**真实时间戳**；速度窗口要防"连发帧"。
