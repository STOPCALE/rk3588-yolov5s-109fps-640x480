# step0 · 自测与变式（合上一切再写）

> 用法：先「复述题」白纸默写 → 再自己走「追问链」（自问自答，模拟面试）→ 最后做「变式题」。
> 复述题与变式题的参考要点在 `docs/teaching/answers/step0-cpp-骨架/self-test-答案.md`；
> **追问链不给答案**（这才是面试训练的意义——有卡壳就回 concept-map 补）。

---

## 一、复述题（合上所有资料，白纸默写）

1. **日常开发 4 条命令**：写在 PC 上、cwd 必须是哪里？各自「一句话作用」是什么？
2. **Git 三仓库图**：画出 `PC → 裸仓库 → 板子工作副本` 的流向；标注每个仓库「允许/禁止」的操作。
3. **CMake 四阶段**：写出四个阶段的名称与命令；再回答：改了 `CMakeLists.txt` 之后，必须重跑哪两步？
4. **六条不可动约定**：至少写出 4 条（如 `cmake_minimum_required` 的版本）及其「违反后果」。

## 二、追问链（只给追问路径，模拟面试官连问 5 层）

**链 A**：从「我改了 `install()` 规则，但运行结果没变化」出发——

1. 为什么改了不生效？→（自己答）
2. 那你执行 `cmake --install` 时，它实际在跑哪个文件？→
3. 这个文件是什么时候生成的？→
4. 那要让它重新生成，需要做什么？→
5. 有没有更保险的日常习惯？（提示：改 CMakeLists 后的动作清单）→

**链 B**：从「板子上能不能直接改代码、直接 commit」出发——

1. 为什么设计成板子只读？→
2. 如果在板子上 `git commit` 了，下一刻 PC 上 `git push` 会发生什么？→
3. 报错长什么样？怎么把板子「救回」对齐状态？→
4. 为什么当初不干脆「两边都能改」？（回忆 scp 时代的三类事故）→
5. 真需要在板子上做实验性改动时，正确姿势是什么？→

## 三、变式题

**变式 1**：板子的 IP 变了（DHCP 重新分配）。从「症状」到「修复验证」，写出完整流程（命令级别），并说明每一步在验证什么。

**变式 2**：给你一台**全新**的 Orange Pi 5，要把它变成这个工程的运行环境。列出从零到「`sync.ps1` 能跑通」的步骤清单（8 步左右；想想哪些是一次性配置、哪些可以脚本化）。

**变式 3**：`tools/check.ps1` 说「all 12 file(s) passed」，但板子上编译失败。列出至少三种可能的原因（提示：本地检查能覆盖什么、覆盖不了什么）。
