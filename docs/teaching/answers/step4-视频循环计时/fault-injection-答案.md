## 故障 · 相机掉一半

**根因（一句话）**：`cap.set(cv::CAP_PROP_BUFFERSIZE, 1)` —— V4L2 缓冲数 =1 触发**除触发时序问题**，
每两帧丢一帧（120fps 实测 62fps）。

**参考排查路径**：
1. 分辨率/格式/帧率打印全对、"恰好一半"——**解码慢/带宽不足是"耗时长"型症状，不会恰好折半**。
2. 对照法：同机 `cam_probe`（工程工具，buffer=2）跑 109 fps → 差异只可能在**你没对照的那个参数**上。
3. 00 §6 S 的排除法：YUYV 与 MJPG 耗时相同、320×240 与 640×480 也相同
   → 不是解码、不是带宽 → 是 **V4L2 时序**。
4. 缓冲数对照表：=1 → 62fps；=2/4/8 → 109.4~109.5fps。

**修复（一行）**：

```c
cap.set(cv::CAP_PROP_BUFFERSIZE, 2);   // =1 会每两帧丢一帧
```

**验证**：重跑 → 帧率 **≥100 fps**（预期 ~109.4），`read` 平均从 ~16.1 ms 降到 ~9.13 ms。

**工程含义**：主工程取 **2**（积压上限 ~2 帧 ≈18ms，兼顾实时性与吞吐）——
这也呼应 §4 的"延迟小且稳定"目标：缓冲不是越大越好，=1 更糟（反而丢帧）。
