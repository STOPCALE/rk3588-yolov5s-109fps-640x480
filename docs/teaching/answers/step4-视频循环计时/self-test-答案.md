# step4 · 自测答案（对照 `step4-视频循环计时/self-test.md`）

## 一、复述题要点

1. 读字节 ≈0.03 ms（1%）+ JPEG 解码 ≈10.3 ms（99.7%）；BMP 对照：文件大 11.8 倍、耗时反而降到 1/4.4。
2. $T_{循环}=\max(\text{节流周期},\text{单帧工作量})$；33.23 = 30fps 的周期，read 退化为余量 → 和恒定。
3. `lock-freq.sh lock`（CPU×3 + NPU + **dmc**）；`lock-freq.sh` 复核；`taskset -c 4-7` 绑大核。
4. ① OpenCV FFMPEG 后端在板上解 ~15% 帧永久卡死（是它的 bug，不是我们的）；
   ② 显式 GStreamer + `gstreamer1.0-libav` → 300/300；
   ③ 硬解陷阱：`videoconvert` 从 DMA-BUF 搬出 123 ns/px。铁律：**硬解只有下一环直吃 DMA-BUF 才有收益**。

## 二、追问链（闭合点）

- 链 A：BMP 反证排除 IO（压缩率是唯一变量）→ 慢在解码 → Huffman 逐位 + IDCT 逐像素 →
  三个方向：更小源分辨率 / 硬解（mppjpegdec）/ 降低解码密度；**其中硬解属 B10 自制练习，本课程只给结论不给实现**。
- 链 B：未定频 DVFS 漂移 → run ±19% 甚至"快的反而慢"（旧记录 2880 图快 4.4ms 的真相）；
  dmc 未锁把 run 带偏 19%、read 带偏 53%；迁移是"台阶型"（×1.86，持续不回落），噪声是上下抖动；
  taskset 限定可调度核集 → 消除迁移；区分方法：**看 preprocess（纯 CPU）是否同步变慢**——
  preprocess 稳而 run 慢 → NPU/内存侧；两者都慢 → CPU 或测量污染。

## 三、变式题参考答案

**变式 1**：等的是**解码**。依据：循环和 31.56 ≈ 纯链路实测 31.5 ms/帧（解码受限），
read(6.73) 不是在等时钟（不是 33.1−infer 的形态），而是解码本身的耗时。
**变式 2**：① 锁频三件套 + 复核 dmc；② `taskset -c 4-7`；③ 用 `--fast`（sync=false）避免节流；
④ 指标选"结果吞吐 + 延迟"而非含显示的墙钟；⑤ 每组重复 ≥3 次记录 min/avg/max。
**变式 3**：非节流 +0.34 ms/帧（23.13→22.79）；节流模式**看不出来**——多余时间被 `read` 的
"等时钟余量"吸收了（循环周期恒定，诊断开销被隐藏在余量里）。
