## 一、复述题

1. 默画 `--pipe` 架构图（三个线程 + 两个槽 + 池 + maxPending）。
2. 默写三根柱子（深拷贝/背压/锁外等待），每条说出"坏的写法→症状→证据数字"。
3. 默写虚假唤醒的正确处理模式（wait 谓词循环），说明 §1.5 修的是什么。
4. 背出流水线四个对照结论（延迟/解耦/拒收语义/喂料间隙账）。

## 二、追问链（连追 5 层"为什么"）

**链 A（并发正确性）**
> Q: 为什么入队必须深拷贝？ → 浅拷贝坏在"谁拥有像素"？ → 为什么这类 bug 是"随机错乱"而不是"稳定错"？ →
> 怎么用测试把随机错乱变成**可判定**？（T1 的做法） → 如果只抄了深拷贝、忘了背压，哪根柱子先塌？

**链 B（流水线设计）**
> Q: 为什么要"最新帧槽"而不是"帧队列"？ → 丢帧和延迟在实时系统里更该保谁？ →
> Little 定律下 maxPending 怎么定？ → 为什么 get 必须非阻塞？ → 
> 采集线程自己不快（41.7fps）时，106fps 的成绩从哪来？

## 三、变式题

**变式 1**：8 线程 + 3 核怎么配？（提示：核是串行资源，多出来的线程只能抢——给出你的配置和预期吞吐）

**变式 2**：帧率目标从 110 改成 60fps——`maxPending`、线程数、模型分辨率哪些可以放宽？哪些不能动？

**变式 3**：显示线程当前"写盘不阻塞主管线"。如果改成在结果线程里**直接 imshow**，
预测：吞吐怎么变、延迟怎么变、怎么验证？
