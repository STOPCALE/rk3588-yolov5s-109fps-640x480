## 故障 · 回车变异

**根因（一句话）**：termios 的 `c_iflag` **没清 `ICRNL`** ——
终端行规程把"输入方向"的 `0x0D`（回车）**翻译成了 `0x0A`（换行）**，
链路里的二进制字节被悄悄改写。

**参考排查路径**：
1. 只有 `0x0D` 变异、`0x0A` 没变 —— 这是"翻译"而不是"丢失/噪声"的特征。
2. 回忆终端默认行为：**ICRNL 默认是开的**（给键盘回车用的）——所以要怀疑它没被清。
3. 在配置代码里数一遍：`ICANON/ECHO` 清了吗（清了）；`IXON/IXOFF` 清了吗（清了）；
   **`INLCR/IGNCR/ICRNL` 清了吗（没有！）**。

**修复（一行）**：

```c
t.c_iflag &= ~(INLCR | IGNCR | ICRNL);   // 二进制协议：翻译三兄弟必须清零
```

**验证**：重跑 → `LOOPBACK PASS (16/16 bytes identical)`，`mismatch = 0`。

**为什么这个 bug 在真实链路里"看起来很吓人"**：
只要包的载荷里出现 `0x0D`，**CRC 必然对不上 → 整包被接收端丢弃**；
而用"串口助手当文本看"时只看到乱码/换行，很容易误判成"线材/干扰"问题。
同理还能举一反三：`IXON` 开着时，载荷里的 `0x11/0x13` 会被当**软件流控**吞掉——
**所以"全量裸模式"（一次性清干净）比"逐条打补丁"安全**。
