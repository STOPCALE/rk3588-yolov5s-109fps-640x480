## 故障 1 · 帧被偷换（结果随机的"错乱"，一改就全对）

- **坏版本**：`docs/teaching/fault-injection/step5-01-帧被偷换/`
- **症状描述**：程序模拟"提交帧 → 假推理 → 校验帧内容"。提交时每帧写入唯一编号（`seq`）。
  运行结果：**几乎每帧都报 `tag mismatch`**（读到的是主线程**下一次覆写**后的内容），
  校验计数器一路飙红。把某一行加一个"复制动作"后，**不一致数瞬间归零**。
- **你的目标**：定位根因（一句话）+ 修复 + 让 `mismatch = 0`。

### 构建运行

```bash
g++ -std=c++14 -O2 steal.cc -o steal -pthread   # PC 或板子都行
./steal
```

## 故障 2 · 流水线串行化（三个工人只有一个在干活）

- **坏版本**：`docs/teaching/fault-injection/step5-02-流水线串行化/`
- **症状描述**：程序用 3 个 worker（每个"推理"假睡 24ms），先跑**阻塞**模式：
  400 个任务吞吐 ≈ **41~42 fps**；随后打印同一份代码里"另一种取结果方式"的对照——
  吞吐跳到 **120+ fps**。3 个工人看起来都在，为什么阻塞模式只能用出一条流水线的速度？
- **你的目标**：解释两种模式的差别（一句话）+ 找出阻塞模式里那个让流水线退化的调用 + 修复到 **≥110 fps**。

### 构建运行

```bash
g++ -std=c++14 -O2 pipeline.cc -o pipeline -pthread
./pipeline
```
