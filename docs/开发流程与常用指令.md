## 1. 一次性配置（每台新电脑只做一次）

### 1.1 SSH 免密登录

**① PC 上生成密钥（已有则跳过）**

```cmd
ssh-keygen -t ed25519 -C "windows-pc"
```

一路回车，密码留空。

**② 把公钥装到板子**

cmd：
```cmd
type %USERPROFILE%\.ssh\id_ed25519.pub | ssh orangepi@192.168.3.226 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

PowerShell：
```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh orangepi@192.168.3.226 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

**③ 验证（不输密码直接输出 OK 即成功）**

```cmd
ssh orangepi@192.168.3.226 "echo OK"
```

### 1.2 配置 SSH 别名（强烈推荐，命令能短一半）

新建/编辑 `C:\Users\<你的用户名>\.ssh\config`（**文件名必须是 `config`，没有扩展名**）：

```ssh-config
Host board                  # ← 这里写的是"别名"，名字随便起
    HostName 192.168.3.226  # ← 这里才是真正的 IP / 域名
    User orangepi
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 6
```

> 🔴 **最容易搞错的点：`Host` 后面跟的是「别名」，不是 IP。**
>
> - 写成 `Host 192.168.3.226` → 你只能用 `ssh 192.168.3.226`，
>   而 `ssh board` 会报 `Could not resolve hostname board`
> - 别名想叫什么就叫什么（`board` / `rk3588` / `orangepi` 都行），关键是 `HostName` 里填对 IP
> - 编辑器把它存成 `config.txt` **也不行**，SSH 只读 `config`
> - 改完 config 后，**已经开着的终端不会重新读取**，需要重开一个 PowerShell

完整的样子（可以写多段，SSH 按顺序匹配）：

```ssh-config
Host board
    HostName 192.168.3.226
    User orangepi
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 6

Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/id_ed25519
```

配好后：

| 原命令 | 简写 |
|---|---|
| `ssh orangepi@192.168.3.226` | `ssh board` |
| `scp f.txt orangepi@192.168.3.226:~/` | `scp f.txt board:~/` |
| `git clone orangepi@192.168.3.226:~/myproj.git` | `git clone board:~/myproj.git` |
| VS Code Remote-SSH 主机 | `board` |

### 1.3 板上的 Git 身份（每个新仓库一次）

```bash
cd ~/myproj
git config user.name  "orangepi"
git config user.email "orangepi@orangepi5"
```

## 2. 工作模式：**PC 是唯一真源，板子只做编译/验证**

```
┌─────────────────────────────────┐         ┌────────────────────────────────┐
│  Windows PC  ← 唯一真源           │         │  RK3588 开发板 (只读部署目标)     │
│                                 │         │                                │
│  VS Code (本地模式, 全速编辑)      │         │  /home/orangepi/myproj         │
│    ↓ 编辑                        │         │    ├── CMakeLists.txt          │
│  E:\desk\学习\C++\mytest\new      │         │    ├── src/ include/ model/    │
│                                 │         │    └── build/  install/        │
│  git commit → git push ─────────┼──SSH───►│  /home/orangepi/myproj.git     │ ← 裸仓库
│                                 │         │           ↑                    │
│                                 │         │    git pull --ff-only          │
│                                 │         │           ↓                    │
│                                 │         │  cmake --build → 运行验证        │
└─────────────────────────────────┘         └────────────────────────────────┘
```

**核心规则（务必遵守）：**

| 规则 | 原因 |
|---|---|
| **只在 PC 上编辑代码** | 本地编辑全速响应，体验最好 |
| **板子上永远不编辑、不 commit** | 板子只 `git pull --ff-only`，保证永远不会分叉 |
| **同步只用 Git，不再用 scp 传代码** | scp 传单文件容易漏、容易覆盖，是之前"改了不生效"的根因 |
| **`build/`、`install/` 不进 Git** | 已在 `.gitignore` 中 |
| **板子只负责"编译→运行→把报错贴回来"** | 定位清晰，不产生第二份需要维护的源码 |

## 3. 日常开发流程

### 3.1 开始工作

1. VS Code 打开本地目录 **`E:\desk\学习\C++\mytest\new`**（注意是**本地模式**，左下角不显示 `SSH:`）
2. 打开一个 PowerShell 终端备用（用来同步到板子）

### 3.2 编译 + 运行（在板子上执行）

两种方式，任选。

**方式 A：一条命令搞定（推荐，见 `tools\sync.ps1`）**

```powershell
cd "E:\desk\学习\C++\mytest\new"
.\tools\sync.ps1
```

脚本会依次完成：`git commit` → `git push` → 板子 `git pull` → 板子 `cmake --build`。

**方式 B：手动分两步**

```powershell
# ① PC 上：提交并推送
cd "E:\desk\学习\C++\mytest\new"
git add -A
git commit -m "描述这次改了什么"
git push board master
```

```bash
# ② 板子上：拉取 + 编译
ssh board
cd ~/myproj
git pull --ff-only

# 只在 CMakeLists.txt 改动后或新增/删除源文件后才需要重新配置
cmake -B build -S .
cmake --build build -j8
cmake --install build
```

**直接一条 SSH 命令完成（不开交互终端）：**

```powershell
ssh board "cd ~/myproj && git pull --ff-only && cmake -B build -S . && cmake --build build -j8"
```

### 3.2.1 运行验证

```bash
# 板子上
cd ~/myproj/install/my_rknn_yolov5_demo_Linux
./my_rknn_yolov5_demo ./model/RK3588/best.rknn <视频路径>
```

> ⚠️ 板子目前**没有摄像头**，`<视频路径>` 请传视频文件，不要传 `0`。

> 增量编译时 `cmake -B build -S .` 可以省略，直接 `cmake --build build -j8`。
> 但**新增/删除源文件后必须重新配置**。

### 3.3 新增源文件时的固定动作

1. 创建 `src/xxx.cc`
2. 在 `CMakeLists.txt` 的 `add_executable` 里**加一行** `src/xxx.cc`
3. `cmake -B build -S .` 重新配置
4. `cmake --build build -j8`

**CMake 规定：`add_executable` 里列出的每个文件都必须真实存在**，否则报
`Cannot find source file: ...`。还没写的文件可以先注释掉：

```cmake
add_executable(my_rknn_yolov5_demo
        src/main.cc
#        src/postprocess.cc
#        src/preprocess.cc
)
```

### 3.4 把板子上的报错日志取回本地

编译失败时，拉回本地慢慢看比在 SSH 里滚屏舒服：

```powershell
# 编译并把完整输出存到板子的 /tmp/build.log
ssh board "cd ~/myproj && cmake --build build -j8 2>&1 | tee /tmp/build.log"

# 拉回本地
New-Item -ItemType Directory -Force -Path "E:\desk\logs" | Out-Null
scp board:/tmp/build.log "E:\desk\logs\build.log"
```

只想看最后的错误：

```powershell
ssh board "cd ~/myproj && cmake --build build -j8 2>&1 | tail -40"
```

### 3.5 备份

**PC 就是真源，所以"从板子备份"这一步不再需要了。** 要做的是把 PC 的仓库推到远端：

```powershell
cd "E:\desk\学习\C++\mytest\new"
git remote add github <你的远程仓库地址>     # 只需一次
git push github master
```

> 板子的裸仓库 `~/myproj.git` 也算一份备份，但它跟着板子走 —— SD 卡坏了就一起没了。
> 重要节点请推到 GitHub / Gitea 等远端。

### 5.5 常见 Git 故障恢复

| 现象 | 原因 | 解决 |
|---|---|---|
| `not in a git directory` | `git config` 跑在 `git init` 之前 | 先 `git init` |
| `src refspec master does not match any` | 本地分支名不是 `master`（可能是 `main`） | `git branch -M master` |
| `Could not resolve hostname board` | SSH 别名没配或没生效 | 检查 `~/.ssh/config` 的 `Host board` 段；重开终端 |
| `destination path 'xxx' already exists` | 目录已存在 | `rmdir /s /q xxx`（cmd）或 `Remove-Item -Recurse -Force xxx` |
| `You appear to have cloned an empty repository` | 源仓库没有任何 commit | 先在源仓库 `git add -A && git commit` |
| `refusing to merge unrelated histories` | 两边历史无关（各自 `git init` 过） | `git push -f`（PC）或板子 `git reset --hard origin/master` |
| `! [rejected] ... non-fast-forward` | 板子上有本地提交，和 PC 分叉了 | 板子执行 `git reset --hard origin/master`（板子本就该只读） |
| `Your local changes would be overwritten` | 板子工作区有未提交改动 | 板子执行 `git reset --hard`（会丢弃改动） |
| 提交时提示 `请告诉我您是谁` | 没配 Git 身份 | `git config user.name/user.email` |
| 想撤销最近一次提交但保留改动 | — | `git reset --soft HEAD~1` |
| 想丢弃所有未提交改动 | — | `git reset --hard HEAD` |
| 想丢弃未跟踪的新文件 | — | `git clean -fd`（⚠️ **不加 `-x`**，否则会删掉 `build/`、`install/`） |

### 5.6 板子"只读"原则

| 板子上允许 | 板子上禁止 |
|---|---|
| `git pull --ff-only` | `git commit` |
| `git log` / `git status` / `git diff` | `git add` |
| `git reset --hard`（用于对齐，会丢弃改动） | 直接编辑源码文件 |

> **一旦板子上产生了提交，PC 的 `git push` 就会变成 non-fast-forward 而被拒绝。**
> 记住了：板子只负责"拉下来、编出来、跑起来"。

## 6. 排错手册

| 报错 | 原因 | 解决 |
|---|---|---|
| `does not appear to contain CMakeLists.txt` | 文件名大小写错了（如 `CmakeLists.txt`） | Linux 区分大小写，改名 |
| `cmake: 未找到命令` | 板子没装 cmake | `sudo apt install -y cmake build-essential libopencv-dev pkg-config` |
| `Cannot find source file: src/xxx.cc` | `add_executable` 里列了不存在的文件 | 注释掉或创建该文件 |
| `No SOURCES given to target` | 上一条的连带（目标没有任何有效源文件） | 同上 |
| `Generate step failed` | 上一条的连带 | 同上 |
| `没有指明目标并且找不到 makefile` | 上一步 generate 失败，`build/` 里没有 Makefile | 修好 CMake 错误后 `rm -rf build` 重来 |
| `flags.make: 没有那个文件或目录` | 还没成功编译过（该文件是编译时生成的） | 先让 `cmake --build` 成功 |
| `OpenCV_FOUND to FALSE ... components were not found` | 组件名写错或该模块没编进 OpenCV | 检查 `COMPONENTS` 拼写；按"符号所在的库"选组件 |
| `undefined reference to cv::VideoCapture::...` | 用了 `VideoCapture` 但没链 `videoio` | `COMPONENTS` 里加 `videoio` |
| `undefined reference to TrajectoryPredictor::...` | 只写了头文件，没加对应的 `.cc` | 把 `.cc` 加进 `add_executable` |
| `error while loading shared libraries: xxx.so` | RPATH 不对 / 库不在搜索路径 | 确认 `CMAKE_INSTALL_RPATH` 是 `$ORIGIN/lib`；或临时 `export LD_LIBRARY_PATH=$PWD/lib` |
| `symbol lookup error: xxx: undefined symbol` | 链接期放宽了符号检查，运行期真缺符号 | 检查 `.so` 版本是否匹配 |
| `/bin/bash^M: bad interpreter` | 脚本是 CRLF 行尾 | 板子上 `sed -i 's/\r$//' *.sh`；或 VS Code 设 `"files.eol": "\n"` |
| `git commit` 提示"请告诉我您是谁" | 没配 Git 身份 | `git config user.name/user.email` |
| `You appear to have cloned an empty repository` | 源仓库没有任何 commit | 先在源仓库 `git add -A && git commit` |
| `destination path 'xxx' already exists` | 上次 clone 留下的目录 | 删掉该目录再 clone |
| 注释/中文乱码 | 文件用 GBK 存、按 UTF-8 读 | VS Code 右下角编码 → `Save with Encoding → UTF-8` |
| 改了代码但结果没变 | 编辑与 scp 混用，文件被覆盖 | 用 `md5sum` 对比两边；统一只在一处编辑 |

## 7. 注意事项（踩过的坑，别再踩）

1. **`cmake_minimum_required(VERSION 3.16)`** —— 板子上是 3.16.3，**不要再提高这个版本号**。
2. **`CMAKE_BUILD_TYPE` 必须有默认值**，否则 `CMAKE_<LANG>_FLAGS_<CONFIG>` 全部失效，
   编译出来是 `-O0`（性能腰斩）。
3. **`CMAKE_INSTALL_RPATH` 用 `$ORIGIN/lib`**，不要用绝对路径或相对 CWD 的 `lib`
   （前者换目录失效，后者必须 `cd` 到安装目录才能跑）。
4. **`install(DIRECTORY model ...)` 不要加结尾斜杠** —— 加了会丢掉 `model/` 这一层，
   而代码里硬编码了 `./model/coco_80_labels_list.txt`。
5. **一个 `-I` 路径要精确到"装着 `.h` 的那个目录"**，不是它的祖先目录。
6. **OpenCV 组件按"符号所在的库"选**，不是按头文件
   （`highgui.hpp` 会间接 include `videoio.hpp`，容易造成"编译过、链接炸"）。
7. **串口 `/dev/ttyS4` 需要权限**，当前用户若不在 `dialout` 组，需
   `sudo usermod -aG dialout $USER` 后重新登录。
8. **`/dev/rga` 与视频设备需要 `video` 组权限。**
