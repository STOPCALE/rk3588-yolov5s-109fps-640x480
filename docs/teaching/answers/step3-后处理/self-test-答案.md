# step3 · 自测答案（对照 `step3-后处理/self-test.md`）

## 一、复述题要点

1. `offset=(6a+f)·G + i·W + j`；检查法：obj 系数必须是 `4G`、cls 必须是 `5G`（手册 §1.2）。
2. cx=(σ(tx)·2−0.5+j)·stride；cy 同理；bw=(σ(tw)·2)²·anchor_w；(r)=(bw+bh)/4。
3. 阈值 `qnt_f32` 一次 → 每格取 `obj=data[idx+4G]` → `if (obj<thres_i8) continue` →
   幸存者才做浮点解码。快的原因：一行整数比较被 -O3 **自动向量化**（16 格/次），
   且 151,200 B 全装进 **L2**（00 §6 E）；全量反量化要贵**几百倍**。
4. NMS：按 prop 降序排序 → 贪心取最大，抑制 IoU>0.45 的框；阈值 0.25（置信）/0.45（IoU）。

## 二、追问链（闭合点）

- 链 A：解码贵几百倍 → 整数比较可向量化而浮点解码不能（每格还要乘法/查 anchor）→
  数据 148KB 恰在 L2（无需访存）→ 换成 fp32 不行（体积 ×4、整数比较优势消失）→
  失效场景：候选密度极高（密集小目标）时预筛省不动，且阈值量化误差开始显形。
- 链 B：stride 反推 → 换 480 模型写死也"能跑"但框全偏（静默）→ anchor 是像素单位因为
  解码在 640 像素空间做 → autoanchor 重算过则标准值失配（注释已写明）→
  快速实验：用 B7-1 的 r 手算对照（实测 r 只差 3.8% ⇒ 匹配）✅。

## 三、变式题参考答案

**变式 1**：offset 变成 `(grid·84 + f)` 的二维行主序（无 anchor/stride 维度）；
解码中心直接回归（无需 σ/网格偏移）；预筛字段仍看 obj（在第 4 位或独立分支）。
**变式 2**：`PROP = 5+3 = 8`；通道 3×8 = **24**；`VB_PROP_SIZE=8`；
三层循环不变，cls 部分从 1 个字段变成 3 个（取最大类别或其 sigmoid 分数）。
**变式 3**：0.8 → 0.63<0.8 **不抑制**（同一球留 2 框 → 下游双计）；
0.3 → 0.63>0.3 **抑制**（可能把相邻的真球吞掉）。阈值选择是精度/召回权衡。
