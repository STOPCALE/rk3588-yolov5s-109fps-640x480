**① 先切到工程目录**（每开一个新终端都要做一次）：

```powershell
cd "E:\desk\学习\C++\mytest\new"
```

**② 每天只会用到这 4 条命令：**

| # | 一句话作用 | 在哪台机器 | 命令 |
|---|---|---|---|
| 1 | **本地语法查错**（1 秒，抓拼写/语法/漏 `return`） | PC | `.\tools\check.ps1` |
| 2 | **同步 + 上板编译 + 安装**（一条顶五条） | PC | `.\tools\sync.ps1 -Message "这次改了什么"` |
| 3 | **运行看结果**（不登板子，一行搞定） | PC | `ssh board "cd ~/myproj/install/my_rknn_yolov5_demo_aarch64 && ./my_rknn_yolov5_demo ./model/RK3588/best.rknn"` |
| 4 | **板子 IP 变了 / 连不上** | PC | `.\tools\set-board-ip.ps1 <新IP>` |

**③ 一次完整的开发循环：**

```
改代码  →  .\tools\check.ps1  →  .\tools\sync.ps1 -Message "..."  →  运行看结果  →  回到第一步
（PC）      （PC，1 秒）           （PC，自动上板编译安装）              （ssh board "..."）
```

**③b ⭐ 只要你要看 fps / ms 数字，先做这三件事**（详见《开发流程与常用指令》§0.2.1）：

| # | 做什么 | 命令 |
|---|---|---|
| 1 | **锁频**（CPU×3 + NPU + **DMC**） | `ssh -t board "sudo bash ~/myproj/tools/lock-freq.sh lock"` |
| 2 | 检查是否锁上 | `ssh board "bash ~/myproj/tools/lock-freq.sh"` |
| 3 | **绑大核运行** | `ssh board "bash ~/myproj/tools/run-demo.sh <参数...>"` |

> 🔴 **重启后锁频全部失效**，每次测性能前重做。
> 🔴 漏锁 `dmc` 会让 `run` 慢 **19%**；不绑大核可能被调到小核慢 **1.86 倍**。

**④ 安全底线（三条红线）：**

| 红线 | 说明 |
|---|---|
| 🟢 **日常收工只需要 `exit`** | 只是断开你和板子的连接，**板子继续运行**。不需要关板子 |
| 🟡 **要断电：`.\tools\poweroff.ps1`，然后等指示灯灭** | `sync` 刷盘要时间 —— **灯还亮着就拔电 = 直接拔电** |
| 🔴 **绝不直接拔电源 / 关排插** | ext4 writeback 模式下，正在写的文件会**填成全零** —— 本工程已因此**报废过两次 Git 仓库** |

## 📌 给 AI 的 30 秒上下文（先读这一段）

### 工程是什么
RK3588 上的 **YOLOv5 多线程 NPU 推理工程**（C++14 / CMake），最终目标是做**实时目标跟踪 + 串口下发偏差给下位机**。

### 🔴 路径铁律（第一条，违反就全错）
```
✅ E:\desk\学习\C++\mytest\new                                 ← 用户的工程，唯一真源，只改这里
❌ E:\desk\学习\C++\mytest\rknn-cpp-Multithreading-main\...     ← 旧工程，只读参考，绝不修改
```
- 回复里写**相对路径**时，必须声明"相对于 `E:\desk\学习\C++\mytest\new\`"，否则读者无法判断是哪个工程
- `new/include/` 下有些文件（`rknnPool.hpp`、`ThreadPool.hpp`、`postprocess.h`、`preprocess.h`、`FrameResult.hpp` 等）是**从旧工程复制过来的**，用户尚未重写 —— 点评时要说清楚

### 工作模式（很重要）
```
PC(Windows) 是唯一真源 → git push → 板子裸仓库 ~/myproj.git → 板子 ~/myproj (只读) 编译运行
```
- **只在 PC 上编辑代码**，用 `tools\sync.ps1` 一键同步
- **板子上绝不编辑、绝不 commit**，只 `git pull --ff-only`
- 编辑用 **VS Code 本地模式**，不是 Remote-SSH

### 环境事实
| 项 | 值 |
|---|---|
| 开发板 | Orange Pi 5（RK3588S），SSH 别名 `board`（**IP 由 DHCP 动态分配，会变**，见《开发流程与常用指令》§1.4） |
| 板子系统 | Ubuntu 20.04.6 focal, aarch64 |
| 工具链 | CMake **3.16.3**（apt 版）、GCC/G++ 9.4.0、OpenCV 4.2.0 |
| NPU | rknpu 驱动 0.9.8，通过 **DRM** 暴露（查 `ls /dev/dri/`，**没有** `/dev/rknpu`） |
| 其他设备 | `/dev/rga` ✅、`/dev/ttyS4` ✅、**无摄像头** ⚠️ |

### 项目路径
| 位置 | 路径 |

| PC 本地查错脚本 | `new\tools\check.ps1` |

| 板子裸仓库 | `~/myproj.git` |

### 用户偏好（协作方式）
- 要**一步一步**教：先讲原理 → 再给改动 → 最后给验证方法，**一次只推进一步**
- 用户倾向**自己手写代码**，会撤销 AI 的大段批量修改 → 改动要小而可解释
- 中文交流
- 用户会要求"重新查看文件" → **每次动手前必须读磁盘上的真实内容**（IDE 附件常是缓存）
- **🔴 文件归属规则（2026-09-20 定）**：**工程本体**（`main.cc`/`rkYolov5s.*`/`rknnPool.hpp`/`CMakeLists.txt`/`tools/*.ps1` 等）**一律用户手写**；
  **验证/诊断工具**（`bench_throughput` / `probe_video` / `pool_selftest`）**由 AI 写**，但必须先讲清思路逻辑；
  **AI 新增任何文件前，必须先说明性质（本体/工具）并获许可**。判断尺子见《00》§10

### 硬性约定（不要改）
| 约定 | 原因 |
|---|---|
| `cmake_minimum_required(VERSION 3.16)` 不能再提高 | 板子上 apt 的 cmake 只有 3.16.3 |
| `CMAKE_INSTALL_RPATH` 必须是 `$ORIGIN/lib` | 绝对路径换目录就失效；相对 CWD 的 `lib` 必须 `cd` 才能跑 |
| `install(DIRECTORY model ...)` **不能加结尾斜杠** | 加了会丢 `model/` 这一层，而 `postprocess.cc` 硬编码了 `./model/coco_80_labels_list.txt` |
| `CMAKE_BUILD_TYPE` 必须有默认值 | 为空时所有 `*_FLAGS_<CONFIG>` 失效，编译出来是 `-O0` |
| OpenCV 组件按"符号所在的库"选 | `highgui.hpp` 会间接 include `videoio.hpp`，容易"编译过、链接炸" |
